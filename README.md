# Измерение скорости загрузки (консольная программа)

Небольшой консольный скрипт на Python. Он **10 раз подряд** запрашивает один и тот
же адрес, на каждый запрос дожидается полного ответа и выводит в консоль:

- среднее время запроса,
- общий объём скачанных данных,
- скорость скачивания.

Используется **только стандартная библиотека Python**: виртуальное окружение и
`pip install` не нужны.

## Требования

- Python 3.8 или новее (тесты запускаются на 3.8, 3.10, 3.12 и 3.13)

## Быстрый старт

```bash
git clone https://github.com/magicgoaldev-prog/Download-Speed
cd Download-Speed
python main.py https://example.com/large-image.jpg
```

Замените адрес ссылкой на большой файл (например, изображение). Чем больше
файл, тем заметнее время передачи по сравнению со временем установки соединения.

## Использование

```bash
python main.py <URL> [--timeout СЕКУНДЫ]
python main.py --version
```

| Аргумент | Описание |
| --- | --- |
| `url` | Адрес `http://` или `https://`, который нужно скачивать |
| `--timeout СЕКУНДЫ` | Таймаут подключения и максимальное ожидание данных при «зависшем» соединении. По умолчанию 30 |
| `--version` | Показать версию и выйти |

### Пример вывода

Числа ниже приведены только для примера.

```text
Загрузка https://example.com/large-image.jpg: 10 запросов подряд...
[ 1/10] 2.41 MB за 0.612 с (31.50 Мбит/с)
[ 2/10] 2.41 MB за 0.548 с (35.18 Мбит/с)
...
[10/10] 2.41 MB за 0.541 с (35.64 Мбит/с)

Результат
  URL                   : https://example.com/large-image.jpg
  Запросов              : 10
  Среднее время запроса : 0.551 с
  Всего загружено       : 24.10 MB (24100000 байт)
  Скорость загрузки     : 34.99 Мбит/с (4.37 МБ/с)
```

### Коды завершения

| Код | Значение |
| --- | --- |
| 0 | Все 10 запросов выполнены, итог выведен |
| 1 | Один из запросов завершился ошибкой, итог не выводится |
| 2 | Некорректные аргументы командной строки |
| 130 | Прервано по Ctrl+C |

## Единицы измерения и формулы

| Величина | Единица | Определение |
| --- | --- | --- |
| Время запроса | секунды (с) | От момента непосредственно перед отправкой запроса до чтения последнего байта тела ответа |
| Среднее время запроса | с | Сумма времени 10 запросов / 10 |
| Общий объём данных | MB | Сумма размеров тел 10 ответов. **1 MB = 1 000 000 байт** |
| Скорость загрузки | **Мбит/с** | Общий объём в байтах × 8 / сумма времени 10 запросов. **1 Мбит/с = 1 000 000 бит/с** |
| Скорость (дополнительно) | МБ/с | Общий объём в байтах / сумма времени 10 запросов |

- Скорость считается как **весь объём, делённый на всё время**, а не как среднее
  из десяти отдельных скоростей. Так как в знаменателе сумма времени запросов,
  значение `среднее время × 10` точно совпадает со временем, использованным для
  расчёта скорости.
- Мбит/с (Mbps) — единица, в которой интернет-провайдеры указывают скорость
  тарифа, поэтому результат можно сравнить с тарифом. МБ/с выводится дополнительно,
  потому что браузеры и менеджеры загрузок обычно показывают байты в секунду.

## Поведение программы и принятые решения

| Решение | Причина |
| --- | --- |
| Запросы выполняются строго друг за другом | Каждый замер не влияет на другие запросы |
| Каждый запрос открывает новое соединение | 10 запросов остаются независимыми; DNS, TCP и TLS входят во время каждого запроса |
| Перенаправления выполняются и учитываются | Перенаправление — часть получения адреса, который указал пользователь |
| Отправляется `Accept-Encoding: identity` | Считаются байты, которые реально отправил сервер, а не распакованные данные |
| Тело читается блоками по 64 КиБ и отбрасывается | Большой файл не нужно хранить в памяти, накладные расходы минимальны |
| Остановка при первой же ошибке | Частичный результат нельзя выдавать за результат 10 запросов |
| Только стандартная библиотека | Ничего не нужно устанавливать, скрипт запускается везде, где есть Python |

## Ошибки

Если любой из 10 запросов завершился ошибкой, скрипт останавливается, выводит
номер неудачного запроса и причину в stderr, завершается с кодом 1 и **не**
выводит итог.

Запрос считается неудачным при:

- HTTP-статусе 400 и выше,
- ошибках DNS, соединения или TLS,
- таймауте,
- закрытии соединения до получения объявленного `Content-Length`.

Пустое тело при успешном статусе считается корректным ответом объёмом 0 байт.

## Ограничения

- Результат описывает **этот адрес, с этого компьютера, в этот момент**. Это не
  максимальная скорость вашего интернет-канала: на неё влияют удалённый сервер,
  CDN, Wi-Fi и другой трафик в сети.
- `--timeout` ограничивает фазу подключения и каждое ожидание данных. Это не
  ограничение на общее время скачивания: если сервер отдаёт данные очень медленно,
  но непрерывно, запуск может длиться дольше таймаута.
- Повторные запросы к одному адресу могут обслуживаться из кэша CDN, поэтому
  последующие запросы могут быть быстрее первого.
- Заголовки и служебные данные TLS не считаются скачанными данными. Считаются
  только байты тела ответа.
- Настройки прокси из окружения (`http_proxy`, `https_proxy`) учитываются
  библиотекой `urllib`.

## Разработка

```bash
python -m unittest -v                    # тесты, подключение к интернету не требуется
python -m pip install ruff mypy          # инструменты разработчика (необязательно)
ruff check . && ruff format --check .    # проверка кода и форматирования
mypy                                     # строгая проверка типов
```

В тестах используются подменённые ответы и таймер, а также несколько
интеграционных тестов с временным HTTP-сервером на `127.0.0.1`. Они покрывают
расчёты, последовательное выполнение, остановку при ошибке, HTTP-ошибки,
таймауты и ошибки соединения, обрезанные ответы, перенаправления, пустое тело и
проверку аргументов.

GitHub Actions (`.github/workflows/ci.yml`) запускает линтер и проверку типов
на Ubuntu. Тесты выполняются на Linux, Windows и macOS, а также на нескольких
версиях Python.
